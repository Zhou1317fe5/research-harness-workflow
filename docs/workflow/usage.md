# 日常实验使用指南：双会话极简闭环

做科研实验时，建议把会话拆开：一个会话用强推理模型专注讨论方案和做决策，另一个会话用高配额模型专注写代码和盯训练。

---

## 核心分工

```text
【会话 1：方案与决策】
模型：强推理模型（如 gpt-6-astra / gpt-6.1-sol / claude-opus-5 / claude-fable-5.1）
流程：讨论新想法或分析上一轮结果 → 收敛共识 →「ok 给出spec方案」→「批准，转csv」→ 拿到 CSV 路径
                                  ↓
                        issues/.../*.csv
                                  ↓
【会话 2：代码与执行】
模型：执行模型 / 高配额模型（如 gpt luna / deepseek）
流程：输入「mission issues/.../*.csv」
     自动推进：改代码 → PRERUN 审查 → 托管训练 (rrctl) → 拉回证据 → 输出 review.md
```

---

## 交互流转（四步闭环）

### 1. 方案会话：讨论与定方案
在强模型会话中展开方案讨论：

* **场景 A：全新实验**
  直接说明意图与对照基线：
  ```text
  我想在现有基线上验证 [某假设/新机制]，沿用现有的数据划分与评测口径。
  请和我讨论对照设计、主指标与预算，先形成实验方案，暂不实现。
  ```

* **场景 B：基于已有实验迭代**
  把上一轮产出的 review 总结直接发给模型：
  ```text
  issues/<上一轮目录>/<任务名>.review.md 实验已完成，请分析结果并讨论下一步方向。
  ```

讨论收敛后，让模型出方案：
```text
ok 给出spec方案
```

### 2. 方案会话：转任务清单并取路径
审阅 Spec 方案确认没问题后，指令转成 CSV 清单：
```text
批准，转csv
```
模型会生成并回复唯一的 CSV 路径（如 `issues/<任务目录>/<任务清单>.csv`）。方案阶段到此交接完成。

### 3. 执行会话：直接运行 CSV
开一个全新的执行会话（切到 `gpt luna` / `deepseek` 等高配额模型），把刚才拿到的路径直接喂给它：
```text
mission issues/<任务目录>/<任务清单>.csv
```
模型会按清单自动推进：
1. **改代码与本地验证**：完成实现，检查参数链路与语法。
2. **short-smoke 与 PRERUN**：涉及核心改动时，跑 1~100 步短 smoke，由独立只读会话完成运行前审查。
3. **GPU 托管与首步检查**：提交 `rrctl`，在 30 秒到 2 分钟内确认显存占上、步数走动、Loss 正常，随后静默挂机。
4. **拉回证据与交付**：跑完后自动拉回结果摘要，生成本次实验的复盘文档（位于 `issues/<任务目录>/<任务名>.review.md`）。

### 4. 循环迭代：带回 review.md 继续推进
把执行会话生成的 `review.md` 路径复制回【会话 1】，进入下一轮迭代：
```text
issues/<本次目录>/<任务名>.review.md 实验已完成。请总结分析指标变化与发现，下一步做什么？
```

---

## 中断与断点恢复

如果中途会话退出或断网：
重新打开执行会话，直接再次输入原 CSV 路径：
```text
mission issues/<任务目录>/<任务清单>.csv
```
或者直接输入 `mission`，模型会自动读取本地活跃任务指针，从 CSV 里没完成的行继续往下走，绝不会把已经跑完的实验重复启动。

## 产物与索引速查

| 想看什么 | 位置 |
|---|---|
| 本轮执行交付与复盘 | `issues/<任务目录>/<任务名>.review.md` |
| 当前全局研究主线 | `research_workspace/STATE.md` |
| 已验证的有效结论 | `research_workspace/CONCLUSIONS.md` |
| 历史实验索引台账 | `research_workspace/EXPERIMENTS.csv` |
| 单次实验机器事实与分析 | `research_workspace/experiments/<ExpID>/analysis/analysis.md` |
| 远程原始运行产物 | `remote_artifacts/<ExpID>/<RunID>/` |
