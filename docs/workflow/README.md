# 面向科研的 Harness Engineering：设计哲学与核心机制

用 AI 做科研实验，最大的挑战不是写不出代码，而是算力昂贵、实验周期长，以及模型很容易在负面结果面前事后找补。

普通 Coding Agent 跑科研任务容易遇到三个典型问题：
1. **上下文被杂乱日志冲垮**：几万行训练日志和报错信息灌满窗口，模型思路被噪音带偏。
2. **实验没提升就事后画靶**：指标没涨时，模型总能解释出“发现了有意思的次要现象”，或者建议“再试个变体”。如果跑之前没定死失败条件，任何结果都能被圆回来。
3. **远程显卡空转假死**：命令发上去显示“已启动”，但可能第一秒就因为 OOM 或环境报错退出了，人和模型还在傻等。

针对这些问题，这套工作流把规则定在前面。

> **核心判断**：
> 科研 Harness 要管的是**上下文粒度、实验前的判据、远程运行的物理证据、结果归档和当前结论**。
> 让 AI 在边界清楚的地方快速执行，让人始终保留问题定义、验收标准和科研判断。

---

## 一、四条核心原则

### 1. 上下文比工具数量重要
材料不是越多越好，关键是让模型只读当前真正需要的那部分。
主会话混进几万行终端日志、无关论文摘要，或者一个模型既搜文献又写实现，最后很容易困在自己前面说过的车轱辘话里。更糟糕的是把旧实验推翻过的结论当成真理带进新一轮。
对策是物理隔离：把“当前在做什么（`STATE.md`）”、“跨实验结论（`CONCLUSIONS.md`）”、“本次实验机器事实（`record.json`）”与“海量原始日志（`remote_artifacts/`）”分开存、分开读。平时只看紧凑概要，不让模型批量通读几万行原始日志，只在针对具体疑点核验时定点调阅。

### 2. 实验前把判断标准定死
大模型很擅长事后合理化。结果不如预期，它能说“观察到了反常趋势”；对照失败，它能建议“再微调个超参”。只要事先没约定什么算成功，整个过程就会变成先射箭再画靶。
因此动手改代码前，必须先写成 Spec 方案并由人批准。白纸黑字定死：验证什么假设、跟哪个 Baseline 在什么协议下比、主指标达到多少算成功、什么表现算失败该停。**“失败”必须被明确定义**，杜绝跑完后强行圆场。

### 3. 远程训练不能只看“已启动”
科研最烧钱的是远程 GPU。命令发上去之后，系统返回“已分配 PID/已启动”，但可能第一秒就因为 CUDA OOM、路径错误或死锁挂掉了；或者显卡根本没占上，日志半天不动。
所以启动之后第一件事不是走开，而是通过**首步验证（First-step Gate）**：启动 30 秒至 2 分钟内，严格确认进程存活、显卡占上、步数开始走动（step >= 1）、Loss 表现为有限非 NaN 数值、checkpoint 目录已经创建。首步不通过绝不走开；通过后交由 `rrctl` 低频挂机。

### 4. 工具要少而准
工具越多，模型越容易犹豫、误选，或者被长工具输出拖垮上下文。工具分工清楚就够了：
- 本地代码理解与精准定位；
- 远程托管运行与生命周期管理（`rrctl`）；
- 本地轻量数据处理与指标脱水；
- 结构化实验事实与记忆检索。
工具的存在是为了减少上下文污染和重复劳动，不是为了堆砌功能。

## 二、一轮实验生命周期

```text
① 定方案 (Spec)      人机讨论假设、Baseline 与死标准（逐字批准）
      ↓
② 转清单 (CSV)       生成任务执行唯一事实源，逐行推进与状态恢复
      ↓
③ 本地验证 + 短运行   本地快速检查导入与参数链路；改动核心逻辑跑 1~100 步 smoke
      ↓
④ 运行前审查 (PRERUN)  只读 fresh 子会话审查实现与 Spec 是否一致，严防伪跑
      ↓
⑤ 远程托管 (rrctl)    启动后必过首步检查（显存/Step/Loss）；过门后进入静默等待
      ↓
⑥ 证据拉回与脱水      仅拉回 summary.json、指标与必要日志，大型数据留远端
      ↓
⑦ 事实与结论沉淀      更新单次机器事实 record.json、分析 analysis.md；
                     若认知更新，沉淀至独立 Git 的 CONCLUSIONS.md
```

1. **定方案 (Spec)**：先看当前进展与上一轮结果，明确假设、对照条件、指标阈值和停止条件。Spec 由用户逐字确认后冻结。
2. **转清单 (CSV)**：批准的 Spec 转为任务 CSV。CSV 是执行进度的唯一依据，任务状态、代码提交均在其中记账，随时可以断点恢复。
3. **写代码与本地验证**：按清单实现，跑轻量检查（导入、编译、参数链路）。涉及模型、数据、损失等核心变动时，必须先跑 1~100 步短 smoke。
4. **运行前审查 (PRERUN)**：长训练前由独立只读子会话比对 Spec 审查代码与 smoke 产物，防止“代码能跑但科学方法写错”。
5. **远程训练/评估**：通过 `rrctl` 提交到远程 GPU。启动后严格核验首步，通过后静默等待，无需模型频繁打扰。
6. **拉回证据**：只拉回结论需要的关键产物（`summary.json`、指标摘要、关键日志），大型张量和逐样本追踪数据留在远端。
7. **更新结论**：基于真实结果更新单次实验事实（`record.json`）与分析（`analysis.md`）。若产生了跨实验新认知，同步更新独立 Git 管理的 `CONCLUSIONS.md`。
