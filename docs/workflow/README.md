# 科研工作流：功能、理念与流程

这套工作流把一轮科研实验中的讨论、代码实现、远程运行和结果分析接起来。用户确定研究目标和可接受的投入，agent 按批准的范围推进，并留下可核对的进度和证据。

它适合基线复现、方法改动验证、训练与评估，以及基于已有结果继续分析。项目接入后，仍然使用自己的代码、数据和评测方法。

## 每个阶段在做什么

| 阶段 | 作用 | 完成后能看到什么 | 用户主要参与什么 |
|---|---|---|---|
| 需求讨论 | 把研究问题、对照、预算和验收标准说清楚 | 一份实验方案 | 确认目标、约束和方案 |
| 任务组织 | 将批准的方案拆成可执行任务，记录依赖与进度 | 任务 CSV，以及每项工作的完成依据 | 需求变化时说明新的范围 |
| 代码实现与本地验证 | 修改项目代码，检查参数、配置和局部行为 | 代码改动和实际验证结果 | 补充项目约定或缺少的信息 |
| 运行前检查 | 按风险安排真实短运行和必要的科学实施审查 | 发现的问题、修复依据和运行准备情况 | 需要改变方案或预算时作出决定 |
| 远程训练与评估 | 通过 rrctl 启动、检查并等待实验 | 是否真正开始、当前运行状态、成功或失败的证据 | 按需查看状态，明确暂停或停止要求 |
| 结果分析 | 核对指标与评测条件，分析实验是否支持原先假设 | 结果对比、实验发现和仍未验证的部分 | 讨论结论是否充分、下一步研究什么 |
| 验收与交付 | 对照原先的验收标准检查工作，并保存代码和科研记录 | 交付说明、证据引用和对应版本 | 查看已完成内容及遗留问题 |

这些阶段会按任务需要展开。已有结果的绘图任务通常不需要训练；纯文档修改也不需要科学实施审查。涉及模型、损失、数据或指标的变化，则需要更充分的验证。

## 为什么这样组织实验

先确定问题、对照和判断标准，结果出来后才知道应该回答什么。基线与新方案需要在可比较的条件下评估，研究预算也应在执行前明确。

运行证据与科学判断分别保留。程序正常退出、代码通过测试，只说明一部分工作完成；方法是否有效，还要结合实验设计和结果判断。没有提升的实验也可以提供有用信息，前提是如实记录条件和发现。

研究积累多了以后，先读取当前状态和相关结论，需要核验时再查原始材料。这样既能追溯过去的判断，也能让眼前的讨论围绕当前问题展开。

## 长任务怎样继续

Codex 用户可以在 Goal 模式中引用已经准备好的 CSV，让同一个会话跨回合持续推进这批任务。CSV 记录任务与进度，Mission 工作流规定执行步骤，Goal 负责持续推进目标。推荐用法见[日常使用指南](usage.md#用-goal-模式执行-csv)。

远程实验由 rrctl 管理，周期检查由普通程序执行。同一会话持续等待时，完成或出现需要处理的异常后，agent 接着推进当前 CSV。训练期间可以减少反复读日志和生成进度分析的模型调用。

多个预先确定的阶段可以顺序执行，例如训练后使用对应 checkpoint 评估。后一阶段需要新的科研判断时，任务清单会保留这个判断环节。

遇到失败，工作流保留运行记录和诊断证据，帮助定位原因。恢复中断任务时，先核对已有进展，避免把已经运行的实验再启动一遍。具体使用方式见[日常使用指南](usage.md)。

## 结果怎样成为后续研究的依据

每次实验的结果会关联运行所用的代码和方案。指标摘要与实验分析分别保存，便于核查成绩，也便于判断这次改动说明了什么。

科研记录与召回贯穿整个过程：当前决定、得到支持的发现、待验证的想法和失败经验会保留各自的来源。下一轮工作可以先查相关记录，再决定是否值得重复实验。旧结论改变时，也能查到为什么改变。

已有结果还可以用于画图、选样例和撰写论文正文。需要新增实验或新的对照时，再明确新的方案与执行范围。记录的使用思路见[科研记录与召回](usage.md#科研记录与召回)。

## 哪些能力需要额外准备

| 能力 | 需要准备什么 |
|---|---|
| 需求讨论、任务执行、实验记录 | 模板自带相关技能和程序；按项目安装并填写背景与配置 |
| 远程训练和评估 | 可连接的远程环境、项目依赖、数据，以及真实运行命令 |
| 中文方案和交付说明整理 | 在 agent 环境中安装 humanizer-zh，项目规则要求使用该技能 |
| 代码语义检索与外部资料查询 | 分别配置 fast_context_search 和 smart-search-cli；模板不附带这些工具的服务配置 |
| 本地科研记录与召回 | 按配置教程启用记录入口 |
| Hindsight 辅助检索 | 可选，按[官方仓库](https://github.com/vectorize-io/hindsight)安装服务；[接入配置](installation.md#可选-hindsight)见教程 |

第一次接入时，可先让 agent 检查所需工具和技能是否齐全，再按[项目接入与配置](installation.md)完成准备。

本工作流基于 [Missions](https://github.com/flowing-water1/Missions) 整理，也参考了社区的[入门实践](https://linux.do/t/topic/2260154/1)。
